## 1) DashboardController — hapus N+1 + cache agregat

**File:** `app/Http/Controllers/DashboardController.php`

**ownerDashboard()**
- Ganti loop N+1 "global view" (line 106–111) dengan **satu** aggregated query:
  `Branch::leftJoin('orders', ...)->selectRaw('branches.id, branches.name, COALESCE(SUM(orders.total),0) as revenue')->groupBy('branches.id','branches.name')->orderByDesc('revenue')->get()`.
- Ganti loop 7-day trend (line 116–121) dan branchAdmin trend (line 178–183) dengan **satu** grouped query: `selectRaw('DATE(created_at) d, SUM(total) total')->whereBetween(...)->groupByRaw('DATE(created_at)')` lalu map ke 7 slot tanggal (fill 0 untuk tanggal kosong).
- `topBranch` (line 95): sudah pakai `withSum` — OK, tinggal cache.
- `branchesList` (line 126): bungkus dengan `Cache::remember("branches:list", 300, ...)`.

**Cache invalidation:** tambahkan method flush di model `Branch` (boot::saved/deleted → `Cache::forget('branches:list')`).

**Per-role caching:** owner dashboard agregat dicache dengan key bercabang per tenant — `"dashboard:owner:{$branchId ?: 'global'}"` TTL 120s. Invalidasi: di `OrderObserver` (saved/paid) → `Cache::forget` untuk key branch + global. Hanya data yang benar-benar agregat (revenue/count) yang dicache; `recentOrders` tetap live (data sensitif/sering berubah).

## 3) Queue observers (asynchronous journal posting)

**Migration baru:** `database/migrations/2026_07_29_000001_create_jobs_table.php` — tabel `jobs` + `failed_jobs` (pakai struktur resmi Laravel `queue:table` / `queue:failed-table`). Saat ini belum ada sama sekali → wajib agar `QUEUE_CONNECTION=database` berfungsi.

**Jobs baru:**
- `app/Jobs/PostOrderJournalJob.php` (implement `ShouldQueue`) — bungkus `journalService->postOrderJournal($order)` + award loyalty points. Terima `$orderId`, re-fetch Order (hindari serialized model stale).
- `app/Jobs/PostGrnJournalJob.php` (implement `ShouldQueue`) — bungkus proses GRN: buat InventoryBatch, update stock, update PO item received qty, post journal, cek PO completion. Pindahkan isi blok `if status==confirmed` dari observer ke job.

**Refactor observer:**
- `OrderObserver` — `created()`/`updated()` tidak lagi posting journal inline, melainkan `dispatch(new PostOrderJournalJob($order->id))`. Pertahankan guard `payment_status === 'paid'` & `isDirty('payment_status')`.
- `GRNObserver` — `updated()` dispatch `PostGrnJournalJob($grn->id)` saat `status` jadi `confirmed`.

**Trade-off diakui:** journal jadi asynchronous → owner tidak instan. Mitigasi: TTL cache dashboard pendek (120s) sehingga setelah worker selesai, dashboard revalidate cepat; job gagal masuk `failed_jobs` (terlacak).
